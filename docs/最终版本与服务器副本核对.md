## 并行与优化的真实状态

| 技术 | 当前实现 | 本轮结论/边界 |
|---|---|---|
| TP | 组件构造和 loader 按 rank 分片，attention/linear 归约 | TP8 真模型已做 Graph/eager、质量及负载验证 |
| EP | 同一 PP/CP 坐标内由 DP×TP 派生，token ownership + 变长 all-to-allv；可选 packed | 基本语义有组件/生产测试；TP8 dense-EP Graph 已验证；跨拓扑普通 BF16 严格等价仍有限制 |
| PP | 层分 stage，V1 forward-only 多批队列、P2P 和回收 | 有真实多卡生产测试；不等于训练 DualPipe，不支持本轮整模 Graph |
| DP | 多 EngineCore 副本，支持与 TP/PP/EP 组合和 idle replica | 有不等 batch/空副本测试；DP2×TP2 默认 BF16 反例仍保留 |
| DCP | decode KV/attention 的并行组件与合并逻辑 | 未在本轮 30B 多模态负载矩阵验证；不在当前 Graph 支持组合中 |
| CUDA Graph | 每 GPU rank、每 batch bucket 独立捕获，共同按同一顺序捕获/回放 NCCL；静态地址、动态内容更新 | decode-only；本轮 TP8+EP、PP1/DP1/CP1，图像 encoder/prefill 为 eager；未做多机验证 |
| 数值策略 | 默认严格 Graph 使用 batch-invariant；同策略 eager 作为隔离对照 | 短/长前缀完整 logits/KV 严格通过，不等于与任意 eager 或 HF 逐位相同 |
| 多模态 | 静态图像 patch、Vision Tower、Merger、DeepStack、MRoPE → Thinker 文本 | 真实 ChartQA 256 题；未接音频、视频、Talker/Code2Wav |
| grouped/packed、量化和 profile | 保留当前显式开关、工具和既有历史证据 | 不等于所有开关组合都已整模验收；旧 profile/实验按其对应源码解释 |

## 已通过的验收与仍失败的内容

最终真模型矩阵为 26 档、78 轮、29,952 请求，零请求错误，25,344 次跨条件 token 比较零差异；正常 EOS 的 Graph/eager 质量对照 256/256 完整 token 一致。768 组真实图片/分辨率的主 Merger 和三层 DeepStack 与实际 HF loader 逐位一致。两组 TP8 严格 Graph logits/KV 检查均为 max_abs=0，覆盖 2,048 容量边界。原始证据及吞吐分母见 [最终报告](CUDA_Graph多模态最终验证报告.md)。

必须保留两个限制：HF 完整 token 仅 250/256 相同（本实现准确率 216/256，HF 217/256）；普通 BF16 的 DP2×TP2 EP 与匹配非 EP oracle 的严格 greedy 回归有历史失败。Graph/eager 一致不能消除这两个限制，FP32 expert 策略的通过也不能替代默认 BF16 的失败。

发布前另外重跑默认完整 pytest（在可见 GPU 的同一环境）：**169 passed、10 skipped、12 subtests passed**。它包含可自动运行的 GPU kernel 测试，不能把十项 skip 算作 GPU 并行验收。显式 `PP_TEST_BACKEND=nccl` 的生产 worker 回归为 **5 passed、1 failed**；失败仍为 `test_production_dp_ep_unequal_batches_and_idle_replicas[2-2-1]`，保留原断言。原始日志和状态 JSON 附于发布目录的 `release_audit/`。

生产代码在本次整理中未改变，故没有重复整个 29,952 请求负载矩阵。新增内容是完整证据、原始复现脚本、分支/副本审计以及发布前补测记录。上传使用普通 fast-forward push，不覆盖旧实验分支，不 force push。
