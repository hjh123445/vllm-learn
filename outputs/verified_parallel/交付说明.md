## Profile 怎么采集

入口为 `v9/tests/capture_parallel_window.py`，每个 worker 的 `v9/engine/worker.py` 使用 `torch.profiler` 同时记录 CPU 和 CUDA；通信以实际 NCCL GPU kernel 事件呈现，不用 CPU 调用时长代替 GPU 通信时长。层级标注由模型/算子范围提供。

实际 EP8 和 PP2×EP4 命令、环境变量、模型路径保存在 [运行队列](rollout_trace_056_20261104_152543/queue.json)，各场景的配置、输入输出与 capture metadata 保留在同名子目录（仅纳入小型文本记录）。这些是已执行实验的记录，不是当前本地 Windows 上重新跑出的结果。

发布的 [八卡合并 trace](trace_comparison_056_20261105/custom_ep8_compact_cpu_cuda.json.gz) 与 [rank0 预览](trace_comparison_056_20261105/custom_ep8_rank0_cpu_cuda_preview.json.gz) 是真实事件的裁剪版本：Qwen3-Omni 文本 Thinker、8×A800、EP8、8 条短请求、每条生成 4 token，文件只保留首个 prefill 消息附近窗口；不是完整 HTTP 生命周期，也不是吞吐基准。原始采集 rank5 的部分消息存在事件覆盖缺口，不能据缺失条形直接认定通信没执行。层归属采用时间范围近似匹配，不是完整 CUDA correlation 因果重建。详见 [trace 摘要](trace_comparison_056_20261105/custom_ep8_compact_cpu_cuda.summary.json)。

下载 gzip 文件后可尝试直接导入 Perfetto；如不识别，先用 `gzip -dk 文件.json.gz` 解压，再打开 JSON。压缩包经解压 SHA256 与本地原 JSON 一致性检查。

## 数据与验证边界

- 172.29.226.143 的历史候选矩阵与 172.28.30.56 的后续参考数学矩阵是不同主机/执行路径；请勿交叉拼接为一次优化前后对照。
- `384/384` 表示 12 条合成输入×32 个固定前缀位置的完整 logits 对照，不是任务准确率；默认 batch 形状敏感性尚未完整修复。
- 吞吐运行不启用 profiler；同机基线和失败结果按原记录保留。报告中的历史“待完成”状态不等于最新结论。
- 没有宣称训练 DualPipe/zero-bubble 或完整多模态 serving 已完成。

完整激活/logits 的 `.pt`、未裁剪多 rank 原始 trace、大型实验归档和模型权重未纳入 Git；它们继续保留在原本地 `outputs/verified_parallel` 和远程实验目录。凭据、临时部署脚本、依赖环境及个人简历也不发布。本公开目录不是所有本地文件的完整备份。
